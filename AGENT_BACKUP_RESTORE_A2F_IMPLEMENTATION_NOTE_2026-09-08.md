## What changed

`core/agent_backup.py` was rewritten from the A2 draft into a staged, boundary-checked, self-verifying pipeline: *discover → validate trust boundary → stage into an isolated temp directory → hash the staged bytes → build the manifest from staged bytes → zip staged bytes → close/fsync/verify the temp archive → atomic replace only on a clean verify*. Six blocker classes, each with a concrete code change and a regression test:

1. **Database snapshot correctness.** Replaced `wal_checkpoint(TRUNCATE)` + raw file copy with `sqlite3.Connection.backup()` (SQLite's own online backup API) via `_snapshot_sqlite()`. This is a real point-in-time-consistent copy under SQLite's own locking, not a checkpoint (a checkpoint's busy flag was previously ignored entirely, and even a successful checkpoint says nothing about a writer committing between the checkpoint and a subsequent file copy — exactly what produced A2R's "1 row source, 0 row backup, valid=True"). A deadline via the backup API's `progress` callback turns sustained lock contention into a hard `AgentBackupError` rather than an indefinite hang or a silent partial copy. The staged copy's own WAL is folded via a post-backup checkpoint and its `integrity_check` is required to return `ok`, or the whole build fails. `ledger.db` is never part of this at all — never opened, checkpointed, or read.
2. **Immutable staging boundary.** Every source — SQLite or plain file — is staged into a temp directory this process alone controls before anything is hashed. Plain files are read via `os.open(..., O_NOFOLLOW)` + `os.fstat()` re-verification, closing the TOCTOU window between the boundary check and the read. Archive construction (the zip-write pass) reads only staged bytes, never the original source again — proven by a test that mutates the live source *after* staging completes and confirms the archive still reflects the staged snapshot.
3. **Canonical required-state inventory.** `build_agent_backup()` now hard-fails if, after collection, `state/databases/lumina.db` or `state/preferences/prefs.json` are not among the staged members — directly closing A2R's "zero-member backup verifies as valid" reproduction. Directory enumeration (`os.walk`/`os.listdir`) is wrapped so a real enumeration failure (e.g. a permission-denied subdirectory) raises `AgentBackupError` rather than silently being read as "empty."
4. **Credential and filesystem boundary.** The credentials store's identity (device + inode via `os.stat()`, contents never read) is resolved once and checked against every candidate file. A symlink, a directory-symlink escape, or a hardlink sharing the credentials store's inode is excluded with a warning — verified against a real fake-credentials file with both a symlink and a hardlink pointed at it, confirming zero bytes of the marker value ever enter the archive. Deliberately: a boundary *rejection* excludes only that one file (never escalates to a whole-backup failure, so a hostile or accidental symlink can't become a permanent denial-of-service against backups), while a source *disappearing* mid-staging (a distinct, non-security TOCTOU case) does escalate for required categories, per the mission's explicit "either obtain one proven-consistent copy or fail." The receipt says `canonical_credentials_store_excluded: true`, never the broader, undeliverable claim that the archive "contains no secrets."
5. **Safe destination / publication order.** New `_reject_unsafe_destination()` runs before any collection work: refuses a destination inside `DATA_DIR`, inside `BASE_DIR`, equal to `identity_trailers.json`, or itself a symlink. The build now writes to a temp file, closes and fsyncs it, verifies it, and only then `os.replace()`s it into `dest_path` (with a best-effort containing-directory fsync). A build or verification failure leaves an existing good backup at `dest_path` completely untouched — proven by tests that plant a real backup, force a failure, and confirm the destination's hash is unchanged afterward.
6. **Strict `verify_agent_backup()`.** Full manifest schema validation (root fields, `format_version` as `{major, minor}` ints, per-member required fields/types/enums), exact archive↔manifest binding (every declared member physically present exactly once, every physical entry declared exactly once, no undeclared extras), duplicate/case-fold collision detection on `archive_path` and `logical_id`, path-safety rejection (absolute, `..`, empty segments), and an explicit refusal of a physical `ledger.db` payload or a `regenerate` entry carrying archive fields it must never have. Never raises on a malformed archive — a bad `format_version` shape, non-JSON manifest, or missing `manifest.json` all come back as a structured `{"valid": False, "errors": [...]}` result.

**Baseline provenance (Section 8).** `generate_baseline_hashes()` now hashes only **git-tracked** files at whatever commit is checked out, not "whatever's on disk" — `metadata/shipped_baseline_hashes.json` was generated from the current release tree (verified clean, `HEAD == origin/main` at `ee40259`) and correctly contains 20 entries, `skills/rubber-duck-debugging.md` deliberately absent (it's `.gitignore`'d, never part of the tracked release). `build_agent_backup()` defaults `baseline_hashes_path` to `<base_dir>/metadata/shipped_baseline_hashes.json` if not overridden, so normal production use gets real provenance automatically; if the artifact is missing, every overlay member's provenance truthfully falls back to `unknown` rather than a fabricated classification.

**Other Section 12/13/14 items:** manifest root now carries `lumina_version` (read via static regex parse of `main.py`'s `LUMINA_VERSION` constant — never `import main`, which could trigger app-startup side effects), `source_platform`, `source_data_root`, `backup_mode`; Flight Recorder's `database_metadata` includes the real `core.flight_recorder` retention constants. `build_backup_receipt()` derives every field from the verified archive/manifest, never from intent. fsync now happens strictly after the `ZipFile` context manager closes (the A2R-reproduced ordering bug fsynced mid-write, which can sync an incomplete zip).

## Tests

`tests/test_agent_backup.py` — **60 tests**, fully rewritten, organized by the six blocker classes plus baseline/receipt/durability sections. Every test passes explicit `identity_trailers_path`/`credentials_path` overrides (never the real machine defaults) and operates entirely under `tmp_path`. Notable: the concurrent-writer tests use real threads and real SQLite locks (`BEGIN EXCLUSIVE`) rather than mocks, to prove the online backup API genuinely waits out contention and genuinely fails past a deadline rather than asserting on a mocked call count.

Full project suite: **3623 passed, 0 failed**, native exit 0 (452s). This is exactly `3584 (prior baseline) − 21 (old agent_backup suite) + 60 (new suite) = 3623` — confirms the rewrite replaced its own prior test file cleanly with no other regressions anywhere else in the suite.

## Self-adversarial pass (Section 17)

Before writing the formal suite, each of A2R's six blocker classes was independently re-attacked by hand against the repaired code (transcript-verified live in this session, not merely inspected):

| A2R reproduction | Status after repair |
|---|---|
| Stale/inconsistent DB snapshot under a concurrent writer | **RED — blocked.** A held exclusive lock that releases before the deadline: snapshot correctly waits and captures the fully-committed row count. A lock held past the deadline: raises `AgentBackupError`, never a silent partial/stale copy. |
| Credential alias via symlink, hardlink, or directory-symlink escape | **RED — blocked.** All three attempted against a real fake-credentials file with a unique marker value; confirmed zero bytes of the marker anywhere in the resulting archive, in all cases. |
| TOCTOU between hash(source) and zip.write(source) | **RED — blocked.** Source mutated after staging: archive reflects the staged snapshot, not the mutated live file. Source deleted mid-staging: raises `AgentBackupError` for a required category rather than silently producing a truncated archive. |
| Bad publication destroying the prior good backup | **RED — blocked.** A forced build failure and a forced verification failure were both tested against an existing real backup at `dest_path`; its sha256 was confirmed unchanged after each. |
| Empty/near-empty required-state backup verifying as valid | **RED — blocked.** `build_agent_backup()`'s post-collection presence check and `verify_agent_backup()`'s zero-member/missing-primary-database check both independently refuse this. |
| Permissive verifier (raises on malformed input, misses schema/namespace violations) | **RED — blocked.** Malformed `format_version`, missing declared members, wrong size/hash, undeclared physical members, duplicate zip entries, absolute/`..` paths, case-fold collisions (the literal `Duck.md`/`duck.md` case), a physical `ledger.db` payload, and a `regenerate` entry carrying archive fields were all tested; every one returns a structured invalid result, none raise. |

## Remaining risks / known limitations (unchanged from A1, still honest)

- Scheduled/background tasks remain genuinely non-durable (process-local heap) — not something this repair could or should fix.
- This module cannot detect a secret a human manually pastes into a persona, skill, custom tool, or other ordinary text file it is designed to archive verbatim. The receipt says `canonical_credentials_store_excluded`, deliberately not a broader claim.
- Directory-fsync durability is best-effort and not claimed as guaranteed on every filesystem/platform, per the mission's own instruction not to overclaim.
- `metadata/shipped_baseline_hashes.json` is now generated and present in the working tree but is **not** wired into any release-build pipeline — it was produced by a manual one-time run of `generate_baseline_hashes()` against the current clean release checkout, exactly as Section 8 describes as acceptable, but keeping it current on future releases still requires someone (or a future slice) to re-run that generation step at release-cut time.
- No Restore, no Restore UI, no Backup UI wiring, no credential encryption/export, no scheduler persistence — all explicitly out of scope per the mission's hard scope, unchanged.
